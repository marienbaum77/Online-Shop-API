# Online Shop API

REST API интернет-магазина на Django + Django REST Framework. Реализованы
регистрация и авторизация пользователей (JWT), личный баланс, каталог
товаров, корзина и оформление заказов с проверкой остатков и списанием
средств.

## Стек

- Python 3.11, Django 4.2, Django REST Framework
- JWT-авторизация — `djangorestframework-simplejwt`
- PostgreSQL
- Документация API — `drf-spectacular` (Swagger / Redoc)
- Docker + Docker Compose

## Архитектура

Проект разбит на 4 независимых приложения, бизнес-логика вынесена из
вьюшек в отдельные `services.py`:

```
core/                  # настройки проекта, urls, wsgi/asgi
apps/
├── users/              # кастомная модель User (+ баланс), регистрация, JWT, профиль
├── products/            # каталог товаров, CRUD только для админов
├── cart/                # корзина: модели, CartService, вьюшки
└── orders/              # заказы: OrderService, notifications, exceptions
```

- **views.py** — только приём запроса, валидация входных данных, вызов
  сервиса и формирование ответа.
- **services.py** (`CartService`, `OrderService`) — вся бизнес-логика:
  проверка остатков, списание баланса, очистка корзины и т.д.
- **exceptions.py** — доменные исключения заказов (пустая корзина,
  недостаточно товара, недостаточно средств), которые view превращает в
  понятный HTTP-ответ.

## Запуск через Docker Compose

1. В репозитории уже есть файл `.env` с настройками для локальной разработки
   (при необходимости отредактируйте его под себя).
2. Соберите и запустите проект:

   ```bash
   docker-compose up --build
   ```

3. После старта:
   - API доступно на `http://localhost:8000/api/`
   - Swagger-документация — `http://localhost:8000/api/docs/`
   - Redoc — `http://localhost:8000/api/redoc/`
   - Админка Django — `http://localhost:8000/admin/`

При старте контейнер `web` дожидается готовности PostgreSQL, автоматически
накатывает миграции (`migrate`) и собирает статику.

### Создание администратора

```bash
docker-compose exec web python manage.py createsuperuser
```

### Запуск тестов

```bash
docker-compose exec web python manage.py test
```

## Основные эндпоинты API

### Пользователи (`/api/users/`)

| Метод | URL                     | Описание                              |
|-------|-------------------------|----------------------------------------|
| POST  | `register/`             | Регистрация                            |
| POST  | `login/`                | Получить JWT-токены (access/refresh)   |
| POST  | `login/refresh/`        | Обновить access-токен                  |
| GET   | `me/`                   | Профиль текущего пользователя          |
| POST  | `me/top-up/`            | Пополнить баланс `{ "amount": 100 }`   |

### Товары (`/api/products/`)

| Метод              | URL          | Доступ                     |
|---------------------|--------------|-----------------------------|
| GET                 | `/`, `/{id}/`| Любой пользователь           |
| POST/PUT/PATCH/DELETE | `/`, `/{id}/`| Только администратор (`is_staff`) |

Поддерживаются поиск (`?search=`), сортировка (`?ordering=price`) и
фильтр по остатку (`?stock=`).

### Корзина (`/api/cart/`, требуется авторизация)

| Метод  | URL                | Описание                       |
|--------|---------------------|----------------------------------|
| GET    | `/`                 | Текущая корзина с суммой         |
| POST   | `items/`             | Добавить товар `{product_id, quantity}` |
| PATCH  | `items/{id}/`        | Изменить количество `{quantity}` |
| DELETE | `items/{id}/`        | Удалить товар из корзины         |

### Заказы (`/api/orders/`, требуется авторизация)

| Метод | URL          | Описание                                              |
|-------|--------------|---------------------------------------------------------|
| GET   | `/`          | Список заказов пользователя                              |
| POST  | `create/`    | Оформить заказ из текущей корзины                        |
| GET   | `{id}/`      | Детали заказа                                            |

**При оформлении заказа (`POST /api/orders/create/`)** последовательно
выполняются:
1. проверка, что корзина не пуста;
2. проверка остатков по каждому товару в корзине;
3. проверка, что баланса пользователя достаточно;
4. создание заказа и его позиций (с фиксацией цены на момент покупки);
5. списание количества со склада;
6. списание суммы с баланса пользователя;
7. очистка корзины;
8. логирование и уведомление об успешном заказе (логгер `orders`, пишет в
   консоль и в `logs/orders.log`; также предпринимается попытка отправки
   письма через `EMAIL_BACKEND`, по умолчанию — консольный бэкенд).

Всё это выполняется в одной атомарной транзакции с блокировкой строк
(`select_for_update`), чтобы избежать гонок при параллельных запросах.

## Переменные окружения (`.env`)

| Переменная         | Назначение                              |
|---------------------|-------------------------------------------|
| `SECRET_KEY`         | Секретный ключ Django                     |
| `DEBUG`               | `1`/`0`                                   |
| `ALLOWED_HOSTS`       | Список хостов через запятую               |
| `POSTGRES_DB/USER/PASSWORD/HOST/PORT` | Настройки подключения к БД |
| `EMAIL_BACKEND`        | Бэкенд отправки писем (по умолчанию — консоль) |
| `DEFAULT_FROM_EMAIL`   | Email отправителя                         |

## Локальный запуск без Docker (опционально)

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
# поднимите локальный PostgreSQL и укажите его параметры в .env
python manage.py migrate
python manage.py runserver
```
